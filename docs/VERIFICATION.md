## 2. tests/structure.py — структура LISP и зеркало правил
```
OK   MARSHDWG.lsp (utf-8): top-level=90, defun=53, if=92, foreach=12, while=5, bytes=30476
OK   MARSHDWG.lsp (cp1251): top-level=90, defun=53, if=92, foreach=12, while=5, bytes=28132
OK   скобки: глубина 0, все 53 defun на верхнем уровне
OK   dist == src (CP1251/CRLF)
OK   функций md:*: 49, все вызываются
OK   команды: c:MARSHDWG, c:MARSHDWGCFG, c:MARSHDWGFILE, c:MARSHDWGSRC
OK   переменных *md:*: 34
OK   параметры *md:recurse*, *md:scan-paperspace*, *md:require-backup* используются
OK   правила LISP == tests/check_rules.py
ИТОГ: OK
```
Проверка «проглоченных defun» встроена в `tests/structure.py` и работает
по разобранному дереву, а не по подсчёту символов: `lisp_parse` понимает
`\"` внутри строк, поэтому новая строка вида `(strcat a "\\" b)` не даёт
ложного срабатывания. Контракт двойной:

* каждый `defun` стоит на верхнем уровне (иначе форма не закрыта и следующее
  определение оказалось внутри предыдущего);
* всего `defun` ровно `EXPECT_DEFUN = 53` — при намеренном изменении числа
  константу нужно поправить, иначе `FAIL`.

Проверено намеренной поломкой: одна убранная `)` в `md:do-grid` даёт
`FAIL незакрытых форм: 1`, а при 53 → 52 defun без ошибки разбора — `FAIL
defun на верхнем уровне`. Плюс проверка «параметр объявлен, но не читается»
(именно так был незамечен `*md:require-backup*` в 1.1): без неё `structure.py`
писал `ИТОГ: OK`, хотя флаг ничего не делал.
