`moleval/MarshDWD`, в ней — только 1.0 (`50` defun, 24 852 б). Версия 1.1
существует в `moleval/Mark` на ветке `arena/2f9949bf-mark`, путь `dwg-auto/`.
Файлы там читал напрямую через git blob (sha из дерева коммита
`1930d032`), не через `raw.githubusercontent.com` — почему, см. §2.1.

## 2. Блокеры — до приёмки

### 2.1 Ссылка на рабочий файл отдаёт испорченный LISP

`raw.githubusercontent.com` для этого файла **не отдаёт байты из репозитория**:

| Источник | Байт | Что внутри |
|---|---|---|
| git blob `fe7d2126…` | 27 335 | CP1251, `Марка этажа` на месте, sha256 `a60ac668…` |
| `raw.githubusercontent.com/.../dist/MARSHDWG.lsp` | 30 202 | UTF-8-перекодировка «мол-о-хи-бейк»: `Ěŕđęŕ ýňŕćŕ`, строки `Марка этажа` нет |

То есть файл по ссылке из «Шага 1» в AutoCAD загрузится, но
`*md:block-name*` станет `Ěŕđęŕ ýňŕćŕ`, блок в источнике не найдётся,
вместо вставки будет `[ВНИМАНИЕ] в источнике нет блока: …`, а `md:floor-value`
не найдёт маркер `ОП`. Это не проблема кода — это доставка файла.

Лечение в репозитории `Mark`: пометить `dwg-auto/dist/*.lsp` как бинарь-
совместимые (`.gitattributes`):

```gitattributes
dwg-auto/dist/*.lsp  -text  !working-tree-encoding
dwg-auto/src/*.lsp   -text  !working-tree-encoding
```

После правки проверить: размер `dist` 27 335 б, sha256 начинается на
`a60ac668`. Раздавать лучше ZIP-архивом (`MarshDWD-1.1.zip`), а в «Шаге 1»
давать ссылку на Release, а не на `raw`.

В `MarshDWD` это уже сделано — `.gitattributes` объявляет `src/*.lsp` и
`dist/*.lsp` как `-text`.

### 2.2 `*md:require-backup*` объявлен, но не читается

Вхождений в файле — одно, сам `setq`. Поведение при этом верное (проверка
копии безусловная), но флаг вводит в заблуждение: `(setq *md:require-backup*
nil)` ничего не изменит. Либо проверять флаг в `md:run-one`, либо убрать
переменную и не описывать её в README.

### 2.3 Пустой фон штриховки снова ломает идемпотентность

```lisp
(setq c (md:try 'vla-get-BackgroundColor o nil))
(if (and c (= (md:try 'vla-get-ColorMethod c nil) 0))
  nil                                  ; фон уже «Нет»
  (progn … (md:bump "hatch")))
```

Если `c` = `nil` (свойство недоступно), ветка «уже нет» не срабатывает,
изменять нечего, а `bump "hatch"` выполняется. На таких штриховках счётчик
`штриховок` будет расти на каждом прогоне. Достаточно:

```lisp
(if (or (null c) (and (numberp (md:try 'vla-get-ColorMethod c nil))
                      (= (md:try 'vla-get-ColorMethod c nil) 0)))
  nil
  (progn … (md:bump "hatch")))
```

### 2.4 `*md:recurse*` затянет `MARSHDWG_BACKUP` в обработку

`md:collect` обходит все подпапки, в том числе `MARSHDWG_BACKUP` — а там
лежат исходники для откатов. При `(setq *md:recurse* t)` они будут обработаны
и перезаписаны, потому что `md:backup` увидит «копия уже есть» и пропустит
создание новой. Резервная копия перестаёт быть резервной.

```lisp
(if *md:recurse*
  (foreach sub (vl-directory-files folder "*.*" -1)
    (if (and (not (member sub (list "." "..")))
             (/= (strcase sub) (strcase *md:backup-subdir*))
             (vl-file-directory-p (strcat folder "\\" sub)))
      (setq res (append res (md:collect (strcat folder "\\" sub)))))))
```

## 3. Мелочи

**3.1 Безусловный `bump "elev"`.** В `md:do-text` (ветка `*md:elev-layers*`) и
в `md:do-obj` счётчик отметок растёт на каждом прогоне — единственный, который
остался неидемпотентным. В `md:do-text` уже есть `md:set-h`/`md:bg-off`/
`md:set-color`, достаточно считать по их результату, как сделано для изделий.

**3.2 `dim` изменил смысл.** В 1.0 `dim` = «сколько размеров попалось»,
в 1.1 — «у скольких стилей сменился DIMTFILL». Строка журнала всё ещё
называется «размеров: N». Стоит переименовать в `стилей размеров` /
`DIMTFILL`, иначе по журналу нельзя будет понять, что произошло.

**3.3 Наивный сканер скобок из отчёта понимает не всё.** Прогнал его на
файле 1.1: `проглоченных 0, глубина 0` — то есть для текущего файла он
работает. Но `\"` он не распознаёт: в файле 9 строк с `\\"`, каждая даёт по
одной лишней `(` и `)` — сейчас сходится, а любая новая строка вида
`(strcat a "\\" b)` без пары даст ложный `FAIL`. `tests/lisp_parse.py`
экранирование понимает — надёжнее проверять через него: «каждая форма
верхнего уровня — `defun`/`setq`/`princ`».

**3.4 Про «обманчивое поведение парсера».** Проверил: на файле с убранной
одной `)` в `md:do-grid` `lisp_parse.check` бросает
`ValueError: незакрытых форм: 1`, то есть недостающую скобку он **ловит**.
Обманчивым был не парсер, а `ИТОГ: OK` при 48 defun — у `structure.py` не было
контракта на число функций. Формулировку в HANDOFF стоит уточнить, иначе
следующий чат будет искать проблему не там.

**3.5 `md:scan-paperspace` и `TabOrder`.** Если `TabOrder` вернёт `nil`,
лист обрабатывается (правильное умолчание), но модель отсекается только
по `TabOrder`. Надёжнее исключать по имени: `(/= (strcase (md:try
'vla-get-Name lay nil)) "MODEL")`.

**3.6 `md:do-layers`, серые слои:** `(/= (md:try 'vla-get-Color lay nil)
*md:gray-color*)` — при `nil` будет ошибка типа. Практически не встречается,
но `md:try` + `numberp` дешевле, чем разбор падения.

## 4. Что по-прежнему непонятно

1. **Где канон.** 1.1 живёт в `moleval/Mark/dwg-auto`, а рабочая ссылка для
   заказчика — `moleval/MarshDWD`. Пока не перенесено, любой, кто откроет
   `MarshDWD`, получит 1.0. Нужно решение: переносить (и когда) или вести
   дальше в `Mark`.
2. **DWG и дампы.** `input/` пуст, `dump/` отсутствует. Ни `check_rules.py`,
   ни `dryrun.py` на реальных данных здесь не запустить — вся офлайн-проверка
   правил в этой сессии не воспроизводится.
3. **AutoCAD LT?** ObjectDBX и весь ActiveX в LT недоступны — команды не
   запустятся вообще. Если у заказчика LT, нужен другой контур
   (`accoreconsole` + script).
4. **Открытые вопросы заказчику** (в отчёте помечены, повторяю, чтобы не
   потерялись): 2400 или 250 для текста «Марка этажа»; `1` или `01` в атрибуте
   «Этаж»; нужна ли рекурсия по умолчанию; включать ли листы по умолчанию
   (`*md:scan-paperspace*` сейчас `nil`).
5. **Права GitHub.** В прошлой сессии `MarshDWD` был доступен токену только на
   чтение (`403` на push). Пока не выданы `Contents: read & write`, перенести
   1.1 в `MarshDWD` из этой сессии не получится.
