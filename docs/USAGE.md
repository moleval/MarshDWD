# Как работает MARSHDWG 1.2 и что делать по шагам

Версия: Ред. 1.2, `dist/MARSHDWG.lsp`, 28 132 байта, CP1251 + CRLF.
Дата: 2026-11-09. Решение по высоте марки этажа: **2400**, масштаб вставки 1:1.

---

## 1. Что программа делает

Пакетно правит DWG-файлы **без открытия их в редакторе** (через ObjectDBX),
по семи правилам заказчика, и вставляет блок «Марка этажа» с атрибутом «Этаж».
Перед изменением файл копируется в `MARSHDWG_BACKUP`, все действия пишутся в
`MARSHDWG_LOG.txt`.

| № | Правило | Что происходит в файле |
|---|---|---|
| 1 | Выключить 10 слоёв | `A-ANNO-NOTE`, `A-AREA-IDEN`, `A-DETL`, `A-FLOR-IDEN`, `G-ANNO-NOTE`, `G-ANNO-REVC`, `G-ANNO-REVC-IDEN`, `G-ANNO-TEXT`, `I-FURN`, `P-SANR-FIXT` → `LayerOn = false`. **Только выключение**: заморозка, `VP Freeze` и блокировка не трогаются |
| 2 | Серый 251 | `A-ANNO-DIMS`, `A-ANNO-DIMS-100`, `S-GRID`, `S-GRID-IDEN` |
| 3 | Марки осей — красный 1 | все объекты слоя `S-GRID-IDEN`, включая содержимое блоков |
| 4 | Размеры | тексты слоёв `A-ANNO-DIMS`, `A-ANNO-DIMS-100`, `G-ANNO-DIMS` → H = 250, фон «нет»; у размеров в их стиле `DIMTFILL = 0` |
| 5 | Обозначения изделий | тексты `A-DOOR-IDEN`, `A-GLAZ-IDEN`, `A-WALL-IDEN` → H = 225 |
| 6 | Марки изделий и отметки | цвет по символу марки, фон не скрывать; отметки `+0,000` / `-0,010` → фиолетовый 200 |
| 7 | Штриховки | цвет фона → «Нет» |
| — | Марка этажа | блок копируется из источника, вставляется в **0,0** масштабом **1:1**, атрибут «Этаж» = часть имени файла после «ОП» |

Цвета марок (первое совпадение побеждает, `*EI*` проверяется раньше `Д*`):

| Символ | Что | Цвет |
|---|---|---|
| `*EI*` | EI | красный 1 |
| `Д*` | ДВ, ДГ, ДС, ДСВ, ДН, ДПВ | синий 5 |
| `ОК*` | окна | жёлтый 2 |
| `ББ*`, `Б*` | балконные блоки, балконы | жёлтый 2 |
| `ОЛ*` | лоджии | голубой 4 |
| `ВТ*` | витражи | зелёный 3 |
| не подошло | одиночные «А»/«Б» | по слою: `A-GLAZ-IDEN` → 2, `A-DOOR-IDEN` → 5, `A-WALL-IDEN` → 3 |

Имя файла → «Этаж» (часть после **последнего** «ОП», кавычки не пишутся):

| Файл | «Этаж» |
|---|---|
| `7.2 ОП1.dwg` | `1` |
| `7.2 ОП2.dwg` | `2` |
| `7.2 ОП-1.dwg` | `-1` |
| `Объект ГП1.dwg` | блок **не вставляется** |
| `Объект ПОП1.dwg` | блок **не вставляется** (перед «ОП» буква) |
| `Объект ОП.dwg` | блок **не вставляется** (после «ОП» пусто) |

Высота текста внутри блока — **2400**, как в исходнике: блок не масштабируется,
поэтому марка выглядит крупнее соседних текстов H=250/H=225. Это согласовано.

## 2. Что нужно для запуска

| Требование | Почему |
|---|---|
| **Полный AutoCAD**, не LT | ObjectDBX и `vla-*` в LT отсутствуют — команды просто не запустятся |
| `dist/MARSHDWG.lsp` скачан **как raw** | страница `blob/` на GitHub перекодирует CP1251 в UTF-8, кириллица станет мусором и блок не найдётся |
| Признак правильного файла | **28 132 байта**, первая строка `;;; ====...` |
| `Марка этажа.dwg` — файл-источник блока | из него копируется определение блока |
| Папка с DWG для обработки | только выбранная папка (вложенные — по флагу) |
| Слои в файлах не заблокированы | объекты на заблокированных слоях изменить нельзя |

Скачивание — три способа, любой даёт правильный файл. **Только не через
страницу репозитория** (`github.com/.../blob/...`): она перекодирует CP1251
в UTF-8 и кириллица превращается в мусор.

**Способ 1 — архив (самый надёжный).** Скачать `MarshDWD-1.2.zip` из
репозитория, распаковать, взять оттуда `dist/MARSHDWG.lsp`. В архиве файл
лежит байт-в-байт, плюс рядом `КАК-ЗАПУСТИТЬ.txt`.

**Способ 2 — raw-ссылка (PowerShell):**

```powershell
Invoke-WebRequest -Uri "https://raw.githubusercontent.com/moleval/MarshDWD/main/dist/MARSHDWG.lsp" -OutFile "$env:USERPROFILE\Downloads\MARSHDWG.lsp"
```

Если `main` ещё не обновлён (PR не смержен) — в ссылке ветка
`arena/54cba4ea-marshdwd` вместо `main`.

**Способ 3 — архив ветки одним файлом (без git):**

```powershell
Invoke-WebRequest -Uri "https://codeload.github.com/moleval/MarshDWD/zip/refs/heads/main" -OutFile "$env:TEMP\marshdwd.zip"
```

Распаковать, взять `dist/MARSHDWG.lsp`.

**Проверка целостности** (после любого способа):

```powershell
(Get-Item "$env:USERPROFILE\Downloads\MARSHDWG.lsp").Length   # должно быть 28132
Get-FileHash "$env:USERPROFILE\Downloads\MARSHDWG.lsp" -Algorithm SHA256
# начало хэша: 2D7707CF...
```

Второй признак: если открыть файл в Блокноте, кириллица должна читаться
(`Марка этажа`), а не выглядеть как `Ěŕđęŕ ýňŕćŕ`. Первая строка —
`;;; =====...`.

## 3. Четыре команды

| Команда | Что делает | Меняет файлы |
|---|---|---|
| `MARSHDWGSRC` | указать DWG с блоком «Марка этажа» | нет |
| `MARSHDWGCFG` | напечатать действующие правила | нет |
| `MARSHDWGFILE` | прогон на одном файле (обкатка) | да, с бэкапом |
| `MARSHDWG` | пакетный прогон по папке | да, с бэкапами |

`MARSHDWGSRC` действует **до конца сессии AutoCAD**: после перезапуска надо
указать источник заново (или прописать путь в `*md:block-file*` и пересобрать).

---

## 4. Порядок: первый запуск на одном файле

```lisp
(load "C:/Users/molev/Downloads/MARSHDWG.lsp")
```

Ожидаемое приветствие:

```text
MARSHDWG.lsp Ред. 1.2 загружен. Команды: MARSHDWG (папка), MARSHDWGFILE (файл), MARSHDWGSRC (источник блока), MARSHDWGCFG (правила).
```

Дальше:

1. **`MARSHDWGCFG`** — глазами сверить правила с тем, что согласовано.
   Ничего не меняет, печатает список слоёв, цветов, высот и параметров блока.
2. **`MARSHDWGSRC`** → выбрать `Марка этажа.dwg`. Печатает
   `Источник блока: <путь>`.
3. **`MARSHDWGFILE`** → выбрать один боевой файл, например `7.2 ОП1.dwg`.
4. Смотреть журнал в командной строке:

```text
MARSHDWG Ред. 1.2 | источник блока: D:\Проект\Марка этажа.dwg
Файл: D:\Проект\7.2 ОП1.dwg

--- 7.2 ОП1
  [i] копия: D:\Проект\MARSHDWG_BACKUP\7.2 ОП1.dwg
  [OK] «Марка этажа» вставлен в 0,0, Этаж = 1
  [OK] сохранено
  слоёв выкл.: 9, серых: 4, марок осей: 93, стилей размеров: 2,
  текстов размеров: 39, изделий: 81, отметок: 3, высот: 123,
  цветов: 133, масок: 8, штриховок: 150, вставок: 1
```

`слоёв выкл.: 9`, а не 10 — потому что слоя `G-ANNO-NOTE` в файле нет; в
журнале будет `[ВНИМАНИЕ] слой не найден: G-ANNO-NOTE`, это нормально.

5. Проверить в AutoCAD (`СЛОЙ`, `СВОЙСТВА`):
   - 10 слоёв выключены (лампочка жёлтая), заморозка не изменилась;
   - `S-GRID-IDEN` цвет 251, а марка оси на нём — красная;
   - текст размера H = 250, «Фон: нет»;
   - текст изделия H = 225, цвет по таблице;
   - штриховка → фон «Нет»;
   - блок в 0,0, атрибут «Этаж» = `1`, высота текста 2400.
6. **`MARSHDWGFILE` на том же файле ещё раз** — все счётчики должны быть
   нулями. Это приёмочный признак «правила применены», а не «сломалось».
7. Всё устраивает → файл из бэкапа не нужен → переходим к пакету.
   Не устраивает → вернуть файл из `MARSHDWG_BACKUP`.

---

## 5. Пакетный прогон

1. **`MARSHDWG`** → откроется **системный** диалог выбора папки (Windows,
   не AutoCAD).
2. Источник блока берётся из `MARSHDWGSRC`; если не указан — спросит сейчас.
3. Обрабатываются все `*.dwg` в выбранной папке. По умолчанию **без
   вложенных папок**, и `MARSHDWG_BACKUP` в обход не попадает никогда.
4. Журнал один на всю папку: `<папка>\MARSHDWG_LOG.txt` (перезаписывается
   при каждом запуске).
5. Итог:

```text
Обработано файлов: 12 из 12
Журнал: D:\Проект\MARSHDWG_LOG.txt
```

Если файл пропущен — в журнале причина: `[ПРОПУСК]` (нет «ОП» в имени,
блок уже вставлен, нет резервной копии) или `[ВНИМАНИЕ]` (не открылся,
не сохранился, объекты на заблокированных слоях).

---

## 6. Включение листов и вложенных папок

Оба режима по умолчанию **выключены**. Включаются перед запуском:

```lisp
(setq *md:scan-paperspace* t)   ; обрабатывать и листы (Layout), не только модель
(setq *md:recurse* t)           ; обходить вложенные папки
```

Действуют до перезапуска AutoCAD или до повторного `(load ...)` — `load`
перезапишет эти переменные значениями из файла.

Когда включать:

- `*md:scan-paperspace*` — если на листах есть свои тексты/цвета, которые
  тоже нужно привести к правилам. Учтите: это меняет оформление листов,
  поэтому сначала прогоните один файл и посмотрите.
- `*md:recurse*` — если DWG разложены по подпапкам (корпус, секция).
  `MARSHDWG_BACKUP` исключён, резервные копии в обработку не попадут.

## 7. Откат

Бэкапы: `<папка>\MARSHDWG_BACKUP\<имя>.dwg`. Копия делается **один раз** —
при первом прогоне файла. Повторные прогоны её не перезаписывают, поэтому
бэкап всегда содержит исходное состояние.

Вернуть: скопировать файл из `MARSHDWG_BACKUP` поверх рабочего (при закрытом
AutoCAD) — или `_OPEN` бэкапа и `Сохранить как` под нужным именем.

Если папку `MARSHDWG_BACKUP` нельзя создать или записать в неё — файл
**пропускается целиком** (`*md:require-backup* = t`), в журнале
`файл пропущен: нет резервной копии`. Это защита: без копии файл не меняется.
Обрабатывать без копии можно только осознанно:

```lisp
(setq *md:require-backup* nil)   ; НЕ рекомендуется
```

## 8. Что делать, если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| `MARSHDWG.lsp … загружен`, но кириллица в правилах — мусор (`Ěŕđęŕ`) | файл скачан через страницу `blob/` | скачать заново как raw, проверить размер 28 132 б |
| `в источнике нет блока: …` | имя блока не совпало | проверить, что файл не испорчен (см. выше); имя блока — ровно `Марка этажа` |
| `[ПРОПУСК] в имени файла нет «ОП»` | имя без маркера или `ПОП1`/`ОП` без номера | переименовать файл, если блок нужен |
| `[ПРОПУСК] блок уже вставлен в 0,0` | повторный прогон | норма, ничего делать не нужно |
| `[ВНИМАНИЕ] слой не найден: G-ANNO-NOTE` | слоя нет в файле | норма, остальные правила применятся |
| `не изменено объектов на заблокированных слоях: N` | слои заблокированы | разблокировать (`СЛОЙ` → замок), прогнать файл заново |
| `ObjectDBX недоступен` | AutoCAD LT или сбой ActiveX | нужен полный AutoCAD; перезапустить |
| `не открыт: <путь>` | файл занят другим процессом | закрыть файл в AutoCAD/проводнике и повторить |
| `файл пропущен: нет резервной копии` | нет прав на `MARSHDWG_BACKUP` | дать права или выбрать другую папку |
| Счётчики во втором прогоне не нули | правило реально меняет значение ещё раз | пришлите журнал: это баг, проверю |

## 8.1. Как проверить программу самому (без AutoCAD)

Три уровня — от быстрого к полному.

**Уровень 1: файл загружается и правила видны.** В AutoCAD:

```lisp
(load "D:/MARSHDWG.lsp")   ; приветствие: MARSHDWG.lsp Ред. 1.2 загружен
MARSHDWGCFG                ; печатает все правила; ничего не меняет
```

Если приветствие есть, а кириллица в правилах — мусор, файл скачан не через raw
(см. §2), брать архив.

**Уровень 2: один боевой файл (главная проверка).**
`MARSHDWGSRC` → источник, затем `MARSHDWGFILE` → один файл, затем **`MARSHDWGFILE`
по нему же второй раз**. Ожидаемо:

| Что | Первый прогон | Второй прогон |
|---|---|---|
| `[i] копия: …` | есть | `[i] копия уже есть` |
| `[OK] «Марка этажа» вставлен` | есть | `[ПРОПУСК] блок уже вставлен в 0,0` |
| `слоёв выкл.`, `серых`, `марок осей`, `изделий`, `отметок`, `высот`, `цветов`, `масок`, `штриховок` | числа > 0 | **0** |
| `стилей размеров` | число > 0, если в файле был фон | 0 |
| `вставок` | 1 | 0 |

Второй прогон с нулями — это и есть доказательство, что правила применились
и программа работает идемпотентно. Если счётчики не нули — пришлите журнал.

**Уровень 3: полная проверка без AutoCAD (на компьютере с Python).**

```bash
pip install ezdxf
python3 tools/selftest.py
```

Скрипт сам: собирает `dist`, гоняет тесты структуры и LISP-логики, строит
тестовый чертёж (`tools/make_test_dxf.py`), прогоняет по нему все правила,
сверяет каждый пункт (слои, цвета, высоты, маски, фон штриховок, блок и
атрибут «Этаж»), проверяет идемпотентность и обход папок. Ожидаемый конец:

```text
    OK   пункты правил: слои, цвета, высоты, маски, штриховки, блок и атрибут (9 марок)
    OK   идемпотентность: меняется только счётчик «размеров»
    OK   recurse=nil — только папка; recurse=t — вложенные, MARSHDWG_BACKUP исключён
ИТОГ: OK
```

Отдельные команды, если нужно по частям:

```bash
python3 tools/build.py                                  # собрать dist из src
python3 tests/structure.py                              # структура LISP
python3 tests/test_lisp_logic.py                        # таблицы через LISP
python3 tools/make_test_dxf.py                          # тестовые DXF
python3 tools/dryrun.py "out/test/Тест ОП1.dxf" \
        "out/test/Марка этажа.dxf" out/test "Тест ОП1.dwg"
python3 tools/render.py "out/test/Тест ОП1 (проверка).dxf" before.png "до"
```

`tools/dryrun.py` — предпросмотр: правила применяются к DXF и результат можно
открыть в AutoCAD, чтобы увидеть изменения глазами. DXF ≠ DWG: это проверка
правил, а не замена боевому прогону.

**Что офлайн-проверка не покрывает:** ObjectDBX, ActiveX-свойства
(`LayerOn`, `BackgroundFill`, `ColorMethod`), запись DWG и поведение на ваших
реальных файлах. Это проверяется только в AutoCAD по §4–5.

## 9. Чего программа не делает

- **Не открывает файлы в редакторе** — работает через ObjectDBX, окна не
  появляются. Поэтому файлы лучше закрыть в AutoCAD: открытый файл может
  блокировать запись.
- **Не трогает заморозку, `VP Freeze`, блокировку слоёв** — только
  выключение.
- **Не масштабирует блок** «Марка этажа» — 1:1, высота текста 2400.
- **Не удаляет** объекты, слои, блоки. Только меняет свойства.
- **Не работает в AutoCAD LT**.
- **Не обходит вложенные папки и листы** без явных флагов.

## 10. Быстрая шпаргалка

```lisp
;; загрузка
(load "C:/Users/molev/Downloads/MARSHDWG.lsp")

;; настройка (1 раз за сессию)
MARSHDWGSRC              ; → Марка этажа.dwg

;; проверка правил
MARSHDWGCFG

;; обкатка
MARSHDWGFILE             ; → 7.2 ОП1.dwg
MARSHDWGFILE             ; → тот же файл, все счётчики = 0

;; боевой прогон
MARSHDWG                 ; → выбрать папку

;; если нужны листы / подпапки
(setq *md:scan-paperspace* t)
(setq *md:recurse* t)
```

Итоговый журнал пакета лежит в `<папка>\MARSHDWG_LOG.txt`, бэкапы —
в `<папка>\MARSHDWG_BACKUP\`.
