# MARSHDWG — автообработка DWG: слои, цвета, высоты, вставка «Марки этажа»

Отдельный проект. К репозиторию Mark отношения не имеет: свой файл, свои
тесты, никаких зависимостей от `MARK.lsp` и его команд.
Рабочий файл для AutoCAD — `dist/MARSHDWG.lsp` (CP1251 + CRLF),
исходник — `src/MARSHDWG.lsp` (UTF-8), после правки: `python3 tools/build.py`.

## Что делает

Пакетный проход по папке с DWG (или по одному файлу) через
ActiveX/ObjectDBX: **файлы не открываются в редакторе**, окна не появляются.
Перед изменением файл копируется в подпапку `MARSHDWG_BACKUP`, все действия
пишутся в `MARSHDWG_LOG.txt` рядом с файлами.

| № | Требование | Как реализовано |
|---|---|---|
| 1 | Выключить 10 слоёв (`A-ANNO-NOTE`, `A-AREA-IDEN`, `A-DETL`, `A-FLOR-IDEN`, `G-ANNO-NOTE`, `G-ANNO-REVC`, `G-ANNO-REVC-IDEN`, `G-ANNO-TEXT`, `I-FURN`, `P-SANR-FIXT`) | `LayerOn = :vlax-false` (только выключение: заморозка и `VP Freeze` не трогаются; уже выключенный слой не считается изменением) |
| 2 | Серый 251: `A-ANNO-DIMS`, `A-ANNO-DIMS-100`, `S-GRID`, `S-GRID-IDEN` | `Layer.Color = 251` |
| 3 | Марки осей — красный | всем объектам слоя `S-GRID-IDEN` (MTEXT и содержимое блоков «Ось сетки») `Color = 1` |
| 4 | Размеры/Свойства: фон «нет», H = 250 | тексты слоёв `A-ANNO-DIMS`, `A-ANNO-DIMS-100`, `G-ANNO-DIMS` → `Height = 250`, `BackgroundFill = False`; у размеров ещё `Dimtfill = 0` в их размерном стиле |
| 5 | Обозначения изделий H = 225 | тексты слоёв `A-DOOR-IDEN`, `A-GLAZ-IDEN`, `A-WALL-IDEN` → `Height = 225` |
| 6 | Марки изделий и отметки: цвет, задний план не скрывать | цвет по символу марки (таблица ниже), `BackgroundFill = False`; отметки `+0,000` / `-0,010` — фиолетовый 200. `BackgroundFill` читается как `:vlax-true`/`1`/`-1`/`0`/`nil` — разные версии AutoCAD отдают разное |
| 7 | Штриховки: цвет фона «Нет» | `BackgroundColor` штриховки → метод `None` |
| — | Блок «Марка этажа» с атрибутом «Этаж» | блок копируется из файла-источника, вставляется в **0,0** с масштабом 1:1, атрибут заполняется частью имени файла после «ОП» |
| — | Резервная копия | обязательна: если копию сделать не удалось, файл **пропускается** (`*md:require-backup*` = t). `nil` — обрабатывать и без копии, с предупреждением |

Цвета марок (сравнение по тексту, первое совпадение побеждает):

| Символ | Что это | Цвет |
|---|---|---|
| `*EI*` | EI | красный 1 |
| `Д*` | двери: ДВ, ДГ, ДС, ДСВ, ДН, ДПВ | синий 5 |
| `ОК*` | окна | жёлтый 2 |
| `ББ*`, `Б*` | балконные блоки / балконы | жёлтый 2 |
| `ОЛ*` | лоджии | голубой 4 |
| `ВТ*` | витражи | зелёный 3 |

Если символ не подошёл ни под один шаблон (одиночные «А»/«Б» в марках окон на
`A-GLAZ-IDEN`) — берётся цвет по слою: `A-GLAZ-IDEN` → жёлтый,
`A-DOOR-IDEN` → синий, `A-WALL-IDEN` → зелёный.

## Имя файла → атрибут «Этаж»

Из имени берётся часть **после последнего «ОП»**, кавычки не пишутся:

| Файл | «Этаж» |
|---|---|
| `7.2 ОП1.dwg` | `1` |
| `7.2 ОП2.dwg` | `2` |
| `7.2 ОП-1.dwg` | `-1` |

Если «ОП» в имени нет — блок **не вставляется**, в журнале
`[ПРОПУСК] в имени файла нет «ОП»`. Повторная вставка в 0,0 в тот же файл не
делается, поэтому `MARSHDWG` можно запускать повторно.

## Установка и запуск

```lisp
(load "D:/MARSHDWG.lsp")
```

| Команда | Что делает |
|---|---|
| `MARSHDWGSRC` | указать DWG-источник блока «Марка этажа» |
| `MARSHDWGFILE` | прогон на одном файле (обкатка) |
| `MARSHDWG` | пакетный прогон по папке (`*.dwg`) |
| `MARSHDWGCFG` | напечатать действующие правила |

### Обкатка на одном файле

1. `(load "D:/MARSHDWG.lsp")`
2. `MARSHDWGSRC` → выбрать `Марка этажа.dwg`
3. `MARSHDWGFILE` → выбрать `7.2 ОП1.dwg`
4. Ожидаемый вывод:

```text
MARSHDWG Ред. 1.1 | источник блока: ...\Марка этажа.dwg
Файл: ...\7.2 ОП1.dwg

--- 7.2 ОП1
  [i] копия: ...\MARSHDWG_BACKUP\7.2 ОП1.dwg
  [OK] «Марка этажа» вставлен в 0,0, Этаж = 1
  [OK] сохранено
  слоёв выкл.: 9, серых: 4, марок осей: 44, текстов размеров: 39,
  изделий: 81, отметок: 8, высот: 123, цветов: 133, штриховок: 150, вставок: 1
```

5. Проверить в AutoCAD: `СЛОЙ` — 10 слоёв выключены, 4 серых; `СВОЙСТВА` на
   текстах; блок в 0,0 с «Этаж» = 1.
6. Не понравилось — вернуть файл из `MARSHDWG_BACKUP`.
7. Устраивает — `MARSHDWG` на всю папку.

Счётчики в конце файла — число фактически изменённых объектов (слой, цвет,
высота, маска, штриховка, отметки меняются только если значение действительно
другое), поэтому повторный прогон даёт нули: это и есть признак, что правила
применены. Исключение — `стилей размеров`: счётчик растёт, когда у стиля размера
сменился `DIMTFILL`, и на повторном прогоне тоже будет 0.

## Что проверено офлайн (без AutoCAD)

Файлы — DWG AC1027 (2013), переименованные в `.pdf`; разобраны LibreDWG,
правила прогнаны на реальных данных:

* `tests/check_rules.py` — сверка правил с содержимым обоих DWG (слои,
  93 объекта марок осей, 39 размеров, 81 текст изделий, 8 отметок,
  172 штриховки, блок и атрибут `Этаж`);
* `tests/structure.py` — разбор LISP (90 форм, 53 defun), CP1251/CRLF,
  совпадение правил в коде и в проверяльщике, все `md:*` вызываются,
  все `defun` на верхнем уровне (никто не «проглочен» незакрытой формой),
  каждый параметр `*md:*` действительно читается в коде;
* `tests/test_names.py` — таблица «имя файла → Этаж» и «марка → цвет»;
* `tests/test_lisp_logic.py` — те же таблицы прогоняются через **настоящий
  `md:floor-value` / `md:mark-color` из `src/MARSHDWG.lsp`** (интерпретатор
  подмножества AutoLISP, `tools/lisp_sim.py`);
* `tools/dryrun.py` — прогон правил на DXF-конверсии с копированием блока и
  вставкой в 0,0: `out/7.2 ОП1 (проверка).dxf` открывается в AutoCAD как
  наглядный предпросмотр, плюс картинки `out/preview_*.png`.

```bat
python tests\structure.py
python tests\test_names.py
python tests\test_lisp_logic.py
python tools\dryrun.py dump\op1.dxf dump\mark.dxf out "7.2 ОП1.dwg"
```

## Ограничения и открытые вопросы

* DWG 2013 корректно сохраняет только сам AutoCAD, поэтому рабочий контур —
  LISP в AutoCAD; DXF-прогон нужен лишь для проверки глазами.
* Пункт 4 «Размеры/Свойства/Фон» понят так: текст размеров H=250, задний план
  «нет». Если имелись в виду ещё и свойства на палитре — уточните, добавлю.
* Высота текста блока «Марка этажа» остаётся исходной (2400 при масштабе 1:1).
  Если масштабировать под H=250 (≈0,104) — это `*md:ins-scale*`.
* Пункт 6 «задний план — не скрывать» = снять маску у текста
  (`BackgroundFill = False`), подложки не создаются.
* Слоя `G-ANNO-NOTE` в тестовом файле нет — обработчик пишет предупреждение и
  продолжает.
* Объекты на заблокированных слоях не изменяются: в конце файла будет
  предупреждение с их количеством — снимите блокировку и повторите.
* Слой выключается, но объекты на выключенном слое (в том числе внутри
  блоков) всё равно обрабатываются по остальным правилам: выключение слоя
  видимость в модели убирает, а цвет/высоту у невидимых объектов менять
  безопасно. Если такие объекты трогать не нужно — скажите, добавлю фильтр.
* `S-GRID-IDEN` попадает в два правила: слой получает цвет 251 (п. 2), а сами
  объекты слоя (марки осей) — красный 1 (п. 3). Так и задумано: 251 видят
  прочие объекты слоя, марки — красные.
* Листы (Layout) по умолчанию **не** обрабатываются — только модель.
  Включить: `(setq *md:scan-paperspace* t)`.
* Вложенные папки по умолчанию **не** обходятся, только выбранная папка.
  Включить: `(setq *md:recurse* t)`.
* Цвета п. 6 (1/5/2/4/3/200) — приняты по таблице ГОСТ-подобной раскладки;
  если у заказчика другая палитра, правится в `*md:mark-colors*`.
* Раздача файла: `dist/MARSHDWG.lsp` — CP1251. Скачивать только как **raw**
  (`?raw=true` или ссылка на blob), не через веб-страницу GitHub: обычный
  просмотр перекодирует файл в UTF-8 и кириллица превращается в мусор
  (`Ěŕđęŕ ýňŕćŕ`), после чего блок «Марка этажа» не находится. Проверка:
  размер 28 128 байт, первая строка `;;; ====...`.
* AutoCAD LT не поддерживает ObjectDBX и `vla-*` — нужен полный AutoCAD.
  Точная версия пока не подтверждена: ObjectDBX подбирается автоматически
  по `ACADVER` (2013 → 19, 2015–2018 → 20–22).
